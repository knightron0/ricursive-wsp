# ripple/: weight-space programming on CIFAR-10, in several regimes

An LLM agent builds a CIFAR-10 classifier **without training**. Each turn it writes a plan, optionally some analysis code
that the lab runs in a sandbox, and the complete `model.py`. That file defines `build()`, returning a `torch.nn.Sequential`
of standard layers whose weights the agent wrote by hand, by formula or (in some regimes) by direct measurement. The lab
builds the network in an empty sandbox, scores it, and reports back. The held-out sets (val, test) are scored only after
the last turn and never shown to the agent.

This directory is self-contained and independent of the ResNet-18 harness at the top of the repo. The agent is Ripple-65B
(`ricursiveai/ripple-65b-preview`) through OpenRouter by default; any OpenRouter model, or any agent that can read and
write files, also works.

## Regimes

| Regime | Data the agent gets | Starts from | Weights may come from | Feedback each turn | Details |
|---|---|---|---|---|---|
| `data` | the 5,000-image split (10% of train, 500/class) | scratch | constants, formulas, direct measurements on the split; no fitting | split accuracy, per-class accuracy, confusion matrix | [docs/regimes/data.md](docs/regimes/data.md) |
| `generation` | same | an earlier network (`--seed`) | same | same | [docs/regimes/generation.md](docs/regimes/generation.md) |
| `filters` | same | an earlier network | same, and the task asks it to engineer the feature layers | same | [docs/regimes/filters.md](docs/regimes/filters.md) |
| `generalize` | same | an earlier network | same as `filters`, and it must hold out part of the split to judge designs | same | [docs/regimes/generalize.md](docs/regimes/generalize.md) |
| `blind` | **none**: the official CIFAR-10 description only | scratch | constants and formulas only | none (only "builds, N numbers, layers") | [docs/regimes/blind.md](docs/regimes/blind.md) |
| `reasoned` | the split | scratch | constants and formulas written in `model.py`; images and labels meet only in the agent's reasoning | same as `data` | [docs/regimes/reasoned.md](docs/regimes/reasoned.md) |

The exact first message the agent gets in each regime is in [docs/prompts/](docs/prompts/), generated by
`python -m ripple_wsp task <regime>`.

## Quick start

```bash
cd ripple
pixi install                        # or: python3.12 -m venv .venv && . .venv/bin/activate && pip install -r requirements.txt
pixi shell

python -m ripple_wsp prepare --data /path/to/cifar10         # outside ripple/: download, split, val, test
export OPENROUTER_API_KEY=...                                  # or OPENROUTER_KEY_FILE=/path/to/key

python -m ripple_wsp run data --data /path/to/cifar10 --runs /path/to/runs
python -m ripple_wsp log /path/to/runs/<run_id> --summary
```

Requirements: Linux with Landlock ABI 4 or newer (kernel 6.7+), Python 3.12, about 16 CPUs and 96 GB of RAM for the
default limits. Data and run directories must live **outside** `ripple/`, because agent code may read everything under it.
See [docs/setup.md](docs/setup.md).

## Commands

| Command | What it does |
|---|---|
| `prepare --data DIR` | download CIFAR-10 (md5-checked), write `train.npz`, `test.npz`, `sample.npz` (the agent's split: 500/class, seed 0) and `val.npz` (500/class from the rest of train, seed 1) |
| `run REGIME --data DIR --runs DIR [--seed NET_DIR]` | one agent, 15 turns by default; writes `RUNS/<run_id>/` |
| `task REGIME` | print the exact first message of a regime |
| `regimes` | list the regimes |
| `log RUN_DIR [--summary] [--no-reasoning]` | print a run (reasoning, replies, lab feedback, final scores) |
| `eval --net net.pt --data DIR [--sets val,test] --out FILE` | score a saved network (weights-only load, no agent code runs) |
| `generations REGIME --seed NET_DIR --saved DIR --data DIR --runs DIR` | repeated generations: replicates seeded from the best network so far, chosen by val |

## Code

| File | Role |
|---|---|
| `ripple_wsp/cli.py` | command line; regime presets come from `regimes.py` |
| `ripple_wsp/harness.py` | the turn loop: parse reply, run analysis, build and score `model.py`, feedback, final val/test scoring |
| `ripple_wsp/tasks.py` | the task texts, the reminder, the static code scans of `model.py` and the copy-detector limit |
| `ripple_wsp/net.py` | allowed layers, the network check, `prepare` (uint8 HWC to float NCHW) and `classify` |
| `ripple_wsp/runner.py`, `sandbox.py`, `guard.py` | sandbox for agent code: Landlock file/network rules, torch gradient/optimizer/solver locks |
| `ripple_wsp/export.py`, `score.py` | build `model.py` into `net.pt` in an empty box; score `net.pt` (weights-only load) |
| `ripple_wsp/lab/data/lab.py`, `lab/blind/lab.py` | the `lab` module agent code imports (split access, `evaluate` with a per-turn limit, every read logged) |
| `ripple_wsp/focus/*.md` | notes appended to the task by the `filters` and `generalize` regimes |
| `ripple_wsp/llm.py` | OpenRouter streaming client and the file backend |
| `ripple_wsp/data.py`, `evaluate.py`, `generations.py`, `render.py` | data preparation, held-out scoring, the generations loop, the run printer |
